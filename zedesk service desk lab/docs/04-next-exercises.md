## Exercise A — Demonstrate both sides of ticket correspondence

1. Open Emily's ticket #4 as the assigned technician.
2. Send a **Public reply** asking which system is affected and requesting the exact error.
3. Set the ticket **Pending** once the question is sent.
4. Sign into the customer Help Center as Emily and capture the displayed reply.
5. Respond as Emily with a fictional, non-sensitive error message.
6. Return to Support and verify whether the ticket becomes **Open** again.
7. Add an **Internal note** documenting initial findings.
8. Save screenshots of both customer and technician views.

## Exercise B — Resolve a harmless fictional issue

Use a fabricated scenario such as Teams prompting for old credentials (no real production system needed). Record the simulated troubleshooting steps, have Emily confirm the issue is resolved, and submit the ticket **Solved**. Clearly label any steps as simulated, not verified system diagnostics.

## Exercise C — Create a triage view if permissions allow

Create a view that filters tickets with **no assignee** and are not yet solved. Verify that a second end-user ticket appears in the triage queue before assignment and in personal work after assignment.

## Exercise D — Tagging consistency

Define a tiny lab-only category scheme, such as `account_access`, `application_issue`, and `network_issue`. Apply only tags supported by actual requester information. A production team would follow its own published conventions.
